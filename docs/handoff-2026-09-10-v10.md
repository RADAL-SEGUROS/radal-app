## 1. What v10 changed, and why

### 1.1 MÁS is gone; Datos and Analítica took its place

The rail used to end in a collapsed **MÁS** section holding a flat list of a dozen entity routes
(Leads, Expedientes, Clientes, Colocaciones, Cotizaciones, Propuestas, Pólizas, Inspecciones,
Siniestros, Ofertas) plus two greyed "pronto" stubs. That list answered a question the app now
answers in three better places:

- **rows live in Datos** (`/data`),
- **shape lives in Analítica** (`/analytics`),
- **one account's detail lives inside its grupo**.

The rail is now GRUPOS plus five plain rows: **Datos · Analítica · Agente · Compañías ·
Configuración**. The one-item ADMINISTRACIÓN header is gone (more chrome than content), and the two
never-built stubs went with it — **Reportería IS Analítica** now, and **Finanzas** had no surface to
point at, so a permanent "pronto" chip was a promise with no owner.

**The old routes still exist.** `/cases`, `/quotes`, `/policies`, `/clients`, … all still resolve;
group pages deep-link into them. They simply no longer need a rail entry each.

### 1.2 `/analytics` split in two

`/analytics` used to be a KPI dashboard **and** six data tables in one scroll. Now:

- **`/data` — Datos** (`frontend/src/pages/data/index.tsx`): eleven table tabs — Cuentas, Clientes,
  Cotizaciones, Propuestas, Pólizas, Post-venta, Colocaciones, Inspecciones, Ofertas, Leads,
  Documentos. The six former analytics tabs moved into `pages/data/`; the other five are the
  existing standalone list pages rendered with a new `embedded` prop.
- **`/analytics` — Analítica**: visuals only. KPI row + a `?by=` **dimension** picker driving generic
  `BucketBarChart` / `BucketTrendChart`, plus the two fixed charts.

Both speak the same **scope**: grupo · grupo-cuenta · fechas, held in the URL (`?group=`,
`?account=`, `?from=`, `?to=`), so a scoped view is a shareable link. Switching tab **keeps the
scope** and **clears the tab-local params** — `status` means one thing to Cuentas and another to
Colocaciones, and carrying it across reads as "no results" rather than as the leak it is.

**Comparing several groups side by side is deliberately NOT built** — that is the agent's job. The
scope narrows to ONE group, optionally to one grupo-cuenta inside it.

### 1.3 Motion on interactions

`framer-motion` was already installed and used in ~54 places, but only for **mount** entrances;
switching a tab or a vigencia was an instant, unanimated swap — the app felt dead exactly where the
broker clicks most.

Fixed **in the primitive**, not per page (`frontend/src/components/ui/tabs.tsx`): the active marker
is a shared-layout element (`layoutId`, spring) that **slides** from the old trigger to the new one,
and the panel fades+rises on activation. Every tab bar in the app inherits it and none can drift.
The `layoutId` is namespaced per `<TabsList>` with `useId` so two tab bars on one page never animate
into each other.

For what is not a Radix tab, `frontend/src/components/common/motion.tsx` gained **`Swap`** (an
`AnimatePresence` keyed on a value) and `RouteSwap`. Wired into the vigencia switch on the group hub,
the Datos panels and the Analítica re-bucketing.

Everything is skipped under `prefers-reduced-motion`, where the marker falls back to the original
static border — **the active tab must never be unmarked**.

### 1.4 El expediente completo

**"Ver expediente completo"** on the account header pointed at `/cases/:id` — a row in the flat,
now-deprecated Expedientes table, which answered a different question than "show me everything about
this account". It now opens `/groups/:groupId/accounts/:caseId/expediente`
(`frontend/src/pages/groups/expediente.tsx`), inside `GroupShell` so the rail and crumbs stay put.

The page shows identidad + empresas, the **journey with real completion dates**, antecedentes slots,
comparación (columns, named recommendation, `Archivo equivocado` flags), propuesta, pólizas, montos
and every document, plus **Descargar PDF**.

Two properties the server guarantees and the page depends on:

- **Always current.** Nothing is cached into a stored artifact. `GET /case-files/{id}/expediente`
  computes per request and `GET /case-files/{id}/expediente/pdf` renders from the same aggregate, so
  the file the broker sends out cannot disagree with the screen. **No new `PackKind`, no
  `DocumentCategory`, no pack row, no column — and therefore no migration** (there is still no
  Alembic; see non-negotiable 10).
- **Absence is explained.** Every block that has no data carries a Spanish reason, so the broker can
  always tell "not yet" from "broken". Three shapes, and which one you get is derived **from the
  journey**, never in parallel with it:
  - milestone not reached → `Pronto, al cerrar {milestone anterior}`
  - milestone reached, artifact never created → `La cuenta avanzó sin registrar una comparación en Radal.`
  - milestone pending but the artifact already exists → `La comparación ya está cargada; la etapa se cierra cuando el expediente avance desde Bases técnicas.`

### 1.5 Filtros y exportes

Every list **and** every `/summary` on 13 entities now accepts the same vocabulary:
`account_group_id`, `case_file_id`, `date_from`, `date_to` (one FastAPI dependency,
`app/services/analytics.py::scope_filters`). Group resolution is a correlated `EXISTS` per entity —
no denormalised column, no schema change — and **every hop re-asserts `broker_id`**, so a foreign
group is an empty page, never a leak.

`?group_by=` returns a `grouped` envelope (`{group_by, dimensions, money_field, total, total_uf,
buckets:[{key,label,count,total_uf}]}`). **`label` is data-derived server-side** (an insurer's name,
a group's name, `"Sin asignar"`) and enums stay raw, because translating those is the frontend's job
— see `useBucketLabel` in `pages/analytics/charts.tsx`. An unsupported dimension is a **422**, never
a silent ignore.

`POST /exports/{entity}` returns **XLSX or PDF** over **every row matching the filters**, not the
50-row page the client happens to hold — that is the whole point of an export. `GET /exports/entities`
publishes the catalog (per entity: date field, money field, `group_by[]`, columns), and the UI reads
it instead of hardcoding. PNG capture is client-side from the rendered recharts `<svg>`
(`frontend/src/lib/exports.ts`) — no dependency, no round trip. **CSV was explicitly not built**;
XLSX carries types and is what the recipient opens anyway.

Nothing is written to `document` and no S3 key ever appears in an export (non-negotiable 8).

## 2. Errors made & corrections (candid retrospective)

Same discipline as the v9 log. **Six of the eight were caught by driving the app in a real browser,
not by `tsc`/`build` — which were green the whole time.** That is v9's lesson #16 repeating, and it
is the single most useful line in this document.

| # | What was wrong | Why it happened | Correction | Lesson |
|---|---|---|---|---|
| 1 | **Array query params were silently dropped app-wide.** Axios sent `kind[]=account&kind[]=renewal`; FastAPI reads repeated bare keys, so the param stayed `None` and the endpoint returned **everything**. The Cuentas table served endorsements, collections and claims as though they were accounts — **6 rows where 2 were right**. | Nobody had checked the wire format; the default axios serialisation looks correct and fails quietly. | `paramsSerializer` on the axios instance (`frontend/src/lib/api.ts`) repeating bare keys. | A filter that silently doesn't apply is worse than one that errors — it returns plausible data. **Pre-existing bug, not introduced by v10.** |
| 2 | **The scope filter did not filter.** The chips and the URL were shareable, but no table consumed them — the export would have been narrowed while the screen showed everything. | Built the control and the export first and assumed the tables would "just" read the URL. | `useScopeParams()` spread into all 8 tab queries; every `*ListParams` extends `ScopeParams`. | Wiring a control to its *display* is not wiring it to its *effect*. |
| 3 | **Hardcoded the group-by dimension list.** `case_files` cannot group by `insurer`; `proposals` cannot group by `stage`. The picker would have 422'd whichever chart did not support the pick. | Assumed the dimensions were uniform across entities. | Driven from `GET /exports/entities`; each chart asks only for a dimension its own entity supports, and hides otherwise. | Ask the server what it can answer; do not assume symmetry between entities. |
| 4 | **Guessed the expediente contract** in `api/types.ts` while the backend agent was building it, then had to replace all of it. | Two workstreams writing the same contract in parallel with no authority declared. | Types replaced from `backend/app/schemas/expediente.py`. | When splitting work, one side OWNS the contract; the other waits or is handed it. |
| 5 | **Rendered `category` where the server already sent `category_label`.** | Did not read the response shape closely enough. | Use `category_label`. | Read what the payload already gives you before adding a mapping. |
| 6 | **Raw enum keys as UI copy** — `technical_basis`, `policyholder`, `aligned`, `kind`/`origin`/`outcome` in the dimension picker. | The server deliberately leaves enums raw (identities it resolves; enums it does not), and the frontend never picked them up. | `useBucketLabel` + `expediente.role`/`comparisonStatus`/`moneySourceValue` + all 19 dimension labels. | Non-negotiable 4's dynamic-key trap: it compiles, then renders raw on screen. |
| 7 | **`group_by` sent inside `filters`** on the export payload. | Convenience; `ScopeFilterPayload` is `extra="forbid"`, so it 422s. | `group_by` is a sibling of `filters`. | `extra="forbid"` is doing its job — a typo'd filter must never silently vanish. |
| 8 | **Stale copy shipped with the split**: Analítica still promised "las listas consolidadas", which had just moved to Datos. | Moved the feature, forgot the sentence describing it. | Subtitle rewritten. | When a feature moves, its copy moves with it. |

**Backend-side, found by driving the page and sent back to the agent** (both fixed, both now have
regression tests):

- **Block reasons contradicted the journey printed directly above them.** A completed legacy folder
  read "Comparación · completa · 8 oct 2025" and, one card lower, "Pronto, al cerrar Bases Técnicas".
  Cause: reasons were computed from the prerequisite ladder **in parallel with** the journey instead
  of **from** it. Same bug then appeared in the opposite direction (milestone pending, artifact
  present).
- **`UF 1120.1300`** unformatted in a journey summary while the rest of the page read `UF 1.120,13`.

## 4. Backlog & traps for the next session

**Not done, and why it matters:**

- **The full sequential QA walk was never run.** v10 verified only its own four changes. The
  antecedentes upload → AI extraction → bases técnicas → comparación → propuesta → pólizas walk
  (`docs/qa-handoff-chrome.md`) is still owed, and it is where the AI-latency and vision-fallback
  risks live.
- Carried from v9 and still open: **money-core extraction is unreliable** under tool-calling; the
  **vision fallback is stubbed**; **comparison align can run minutes** on the buffered Lambda (do NOT
  change the invoke mode — OAC constraint 4).
- Two known-minor items untouched: Resumen KPI cards still labelled "Cotizaciones/Propuestas", and
  account-new's "El grupo sólo tiene este RUT" showing even when the group has zero empresas.

**New traps v10 introduces:**

- **`git remote` still points at the old repo location.** The push works only because GitHub
  redirects: `git remote set-url origin git@github.com:RADAL-SEGUROS/radal-app.git`.
- **`expose_headers` on CORS is load-bearing.** Without `Content-Disposition` and `X-Radal-Row-Count`
  a cross-origin export loses the server's filename and row count — and loses them *silently*, since
  the file still downloads.
- **Adding a `group_by` dimension is a server-only change** — the picker reads the catalog. But add
  its Spanish label to `locales/*/analytics.json → dimensions`, or it renders as a raw key.
- **Do not put anything but scope keys in an export's `filters`.** `ScopeFilterPayload` is
  `extra="forbid"`.
- **`PageHeader` now takes `embedded`.** A list page rendered as a Datos tab must pass it, or the
  page prints a second `<h1>` under the host's.
- The expediente PDF renders **on demand through Chromium**; it is the slowest endpoint on the page
  and inherits the buffered-Lambda latency risk.
