## 1. The broker journey & structure — as built (v9)

**Radal is the platform; the broker (`corredora`) is the tenant.** The broker works inside a
**group** and drives one **grupo-cuenta** (an account = one ramo × one vigencia) through the
journey. The essential milestones, left to right, are the account's tabs:

```
group (icon) → grupo-cuenta (ramo + vigencia)
   → Antecedentes → Bases Técnicas → Comparación → Propuesta → Pólizas
```

**Ramo — advisory, not a schema.** A ramo is a **recommended-files list + AI context**, nothing
more. It is NOT a field/section form. The broker picks a ramo when **creating the grupo-cuenta**
from a **dropdown** (each option shows "N archivos recomendados"), or authors one inline via a
**"Crear ramo" drawer** (name + optional insurance-line + the recommended-files list: label ·
doc_type · format[word|pdf|pdf/word|image] · required · description). Ramos are **not** managed in
Configuración. We seed exactly two global ramos — **Incendio y Sismo (TRBF)** and
**RC / Ingeniería / Transporte** — and the seed self-prunes any stale global stragglers. Ramo shape:
`recommended_files: [{key,label,doc_type,category,format,required,description}]` + `explanation`
(`backend/app/schemas/antecedentes.py`).

**Sidebar hierarchy.** Group avatar at the top; each **vigencia row expands** into the ramo/account
+ a journey submenu with icons (Resumen · Antecedentes · Bases Técnicas · Comparación · Propuesta ·
Pólizas), each deep-linking `?tab=` (`frontend/src/components/groups/GroupSidebar.tsx`).

**Account tabs** (`frontend/src/pages/groups/account.tsx`): **Resumen · Antecedentes · Bases
Técnicas · Comparación · Propuesta · Pólizas · Renovación · Notas · Bitácora** — the essential
journey, no duplicate "Cotizaciones"/"Propuestas" tabs. The **Journey rail lives only on Resumen**
(restyled), with pending-actions and a whole-account summary; it is not repeated above every tab.

**Antecedentes** (`frontend/src/components/groups/AntecedentesFiles.tsx`): shows the ramo's
recommended-file **slots right away** + a free "Otros archivos" upload, with two subtabs only —
**Archivos** (recommended + free, previews + working authenticated downloads) and **Extracción**
(the per-document AI extraction, keyed by document). It shows **only intake documents**; cotización
docs are scoped out (they belong to Comparación). Uploads accept **PDF/Word/images only — Excel is
rejected** (415, "Sube PDF o Word — para Excel, expórtalo a PDF"); a **vision fallback** for
scanned/image files is detected and flagged (`needs_vision`) but **not yet implemented**.

**Bases Técnicas** = the completed antecedentes rendered to a branded PDF (Playwright) + a UI view;
**warn-not-block** (always renders, incomplete is a warning). The download **downloads the PDF**
(authenticated blob), it does not route away.

**Comparación** — a dynamic, **incremental** comparison expedient. Each cotización is read with a
**tool call** (`extract_budget_proposal`, slim schema: money/period core + open facets +
wrong-file detection). `submit_comparison` builds a **standardized table** (COMMON + EXTRAS, per-cell
value + verbatim) + an **AI recommendation that names a pick**, adaptive batch/merge over the
`AI_COMPARE_MAX_INPUT_CHARS`/`AI_COMPARE_MAX_TOKENS` budgets, and **blocks cleanly if the provider is
down** (no half-baked table). Money core commits to the typed `proposal` columns; the money
premium invariants stay hard, the per-mille rate additivity is a **soft warning** (real insurers
quote a weighted "tasa media" that isn't the sum). Promote supplies the insurer RUT/CMF the PDF
omits.

**Propuesta** — `broker_proposal`, the outbound artifact, built from the comparison via a tool call
(`submit_propuesta`): a **validated minimum core** (insurer identity, insured, vigencia, premium)
+ a free `additional` tail, **account-aware** (insured/vigencia pulled from the antecedentes). Has a
`content_hash` + ratify.

**Pólizas** — **validate-then-dynamic** upload (`POST /policies/upload`): a fixed core check
(corredor / asegurado / vigencia / desglose de prima) gates whether it's really a policy (hard 422
`not_a_policy` with an override), then the full dynamic parse is kept in `policy.payload`;
**account-aware insurer resolution** (the policy PDF names the insurer only by name). Overview lists
each policy + inspect + open original.

**AI layer** (`backend/app/services/ai.py`, `ai_models.py`): tool-calling structured output on
`zai-org/GLM-5.3-Flash` (it **does** support tools), a `tool_call` helper with retries/typed errors,
a **model-tiering registry** (`model_for(AITask)`), context-aware extraction, and one `extraction`
audit row per attempt (suggest → confirm → commit). **Expedient PDFs**: `comparison_pack` +
`proposal_pack` renderers on the branded Playwright pipeline (`GET /comparisons/{id}/pdf`,
`GET /broker-proposals/{id}/pdf`); the backend Docker image installs Chromium.

Verified: **643 backend tests**; `tsc -b` / `npm run build` / `check:locales` clean; the account
view **verified live in a real browser** (Chrome extension) — tabs, journey-on-Resumen, sidebar
submenu, antecedentes (cotizaciones excluded), Bases Técnicas download, ramo dropdown/drawer,
Spanish guard reasons.

## 2. Errors made & corrections (candid retrospective)

The v8 build missed the spec in several places. Each is recorded so the pattern isn't repeated.

| # | What was built wrong | Why it was wrong | Correction | Lesson |
|---|---|---|---|---|
| 1 | **Ramo as a field/section schema builder** in Configuración (Clave/Etiqueta/tipo/Obligatorio/Repetible). | Ramos are advisory + for context; the dynamic processes downstream can't rely on requested fields, and the broker will never fill a schema. | Ramo = recommended-files + context only; removed from Configuración; picked via a dropdown at account creation, created via a drawer. | Don't turn "template for context" into a rigid data contract. |
| 2 | **Journey rail on every tab** (mounted above the tab bar). | Wastes the top space; forces going back to summary to see the journey. | Journey moved into the Resumen tab only, and restyled. | Put an overview element at overview altitude, once. |
| 3 | **Duplicate tabs**: Cotizaciones + Comparación, Propuestas + Propuesta. | Comparación *is* the cotizaciones step; there is one outbound Propuesta. | Tabs de-duplicated to the essential journey, correct order. | Model the journey, not the legacy proposal-centric entities. |
| 4 | **Cotización files shown inside Antecedentes** ("Otros archivos"). | Cotizaciones belong to Comparación; antecedentes is intake only. | Frontend antecedentes list now mirrors the backend `_antecedentes_documents` scoping (excludes insurer_quotation/comparison categories + the `insurer_quotes` section). | Scope both the backend AND the frontend list — the backend fix alone left it leaking. |
| 5 | **Dead download buttons** ("nothing works"). | Used `window.open` on the auth-gated `/documents/{id}/content` route → 401. | New `src/lib/download.ts` — authenticated blob download/preview, wired everywhere. | An auth-gated file needs a fetched blob, not a plain link. |
| 6 | **Excel accepted** on antecedentes upload. | Only PDF/Word (or vision for scans) should be accepted; Excel should be printed to PDF. | Upload MIME gate rejects Excel (415) in intake sections. | Enforce the format contract at the upload boundary. |
| 7 | **Antecedentes schema-section subtabs** (Montos/Siniestralidad/Cuestionario/Slip/Todos). | Antecedentes is free upload + recommended files, not a structured form. | Two subtabs only — Archivos + Extracción (per-document). | The subtabs follow the interaction, not a schema. |
| 8 | **Raw English stage-guard reasons** in the UI (Journey tooltip + pending actions). | User-facing copy must be Spanish (only identifiers are English). | Translated all `STAGE_GUARDS`/transition reasons to Spanish at the source. | Guard reasons are copy, not identifiers. |
| 9 | **Stale seeded ramo** ("Responsabilidad Civil", old v6) lingering active. | The seed upserted by name and never pruned. | Seed self-prunes non-current global ramos; deactivated the straggler. | Idempotent seeds must prune, not just upsert. |
| 10 | **Assumed GLM lacked tool-calling** (used heavy json-mode schemas). | A stale `technical-reference` §8.1 note (true for the retired Llama model, not GLM-5.3). | Moved structured output to tool calls; slimmed schemas; corrected the doc; recorded in memory. | Verify provider capability against the current model, not an old note. |
| 11 | **Comparison batching threshold too low** → the single holistic align **silently committed an EMPTY table** (output overflowed the token cap, truncated JSON parsed as empty, still returned 200 + status=aligned). | No guard against truncation/empty; the input threshold ignored the output budget. | Separate `AI_COMPARE_MAX_TOKENS`; right-sized `AI_COMPARE_MAX_INPUT_CHARS`; hard guards (empty dimensions / `finish_reason=length` → block, never a 200 empty commit). | A successful HTTP status is not a successful result — guard the payload. |
| 12 | **`verbatim` dropped** by the slim extraction (0/N across runs). | The tool field was optional, so the model put wording into the free `value` and left verbatim null. | Made `verbatim` required in the tool schema + prompt. | Require the fields you actually need in the tool schema. |
| 13 | **Recommendation named no pick** (only caveats). | The recommend tool schema didn't require the pick/rationale. | Required them in the dedicated recommend call + prompt, soft-warn fallback. | Same as #12 — require the decisive output. |
| 14 | **Insurer identity absent from cotización/policy PDFs** blocked promote/commit. | Real PDFs name the insurer by name only (dedup is by RUT/CMF, never name — correct). | Reviewer supplies RUT/CMF at promote; policy commit resolves the insurer from the account's accepted proposal. | Provide a human path for identity the document omits. |
| 15 | **Money-core extraction weak under tool-calling** (fills 0–1 of 5 premium fields run-to-run). | GLM-5.3-Flash capability/variance, not schema. | **Not yet fixed** — needs a retry on the money block and/or a stronger COMPARE-tier model. | Some blocks need a retry or a better model; prompt engineering has a ceiling. |
| 16 | **Did not test the UX in a real browser** before reporting "done" (relied on tsc/build + headless screenshots I skimmed). | Compile-green says nothing about the UX being right; this is the biggest process error. | Drove the app live via the Chrome extension — which immediately caught the cotizaciones-in-antecedentes leak (#4) that the screenshots had glossed over. | For UI work, verify by driving the running app, not by trusting compile-green or a skimmed screenshot. |

## 3. Deploy state & backlog

**Deploy (dev):** dev RDS reset to the v9 schema + blank baseline (0 accounts, 25 insurers, the 2
global ramos, `definition`/`insurance_line_id` nullable, new tables present); RDS private again + SG
clean (independently verified). S3 `deploy/backend.env` updated with the v9 AI/media keys
(`MEDIA_BACKEND=s3`, GLM model, timeouts, RDS URL). The Dockerfile installs Chromium. CI
(`.github/workflows/dev-deploy.yml`, OIDC, all 7 secrets present) fires on push to `dev` — this is
its first-ever run. The commit + push is done by the user (the assistant's git writes were
permission-blocked). Live target: `https://dev.radalseguros.cl`.

**Backlog / known items to fix on deployment:**
- **Money-core extraction reliability** (#15) — retry on the premium block or a stronger tier.
- **Vision fallback** for scanned/image antecedentes — detected + flagged, not implemented.
- **KPI card labels** on Resumen still read "Cotizaciones/Propuestas" (counters, cosmetic).
- **Buffered-Lambda latency** — the comparison align can run minutes; the buffered Function-URL/
  CloudFront path may time out on the slowest AI calls (do NOT switch invoke mode — OAC constraint 4).
- **First CI run** — the backend image build now runs `playwright install --with-deps chromium`
  (slower/bigger; the most likely maiden-run snag).
- The four OAC constraints and the migrate-first ordering in `docs/deployment.md` still hold for any
  future column change (there is no Alembic).
