# Radal — Internationalization (i18n)

The Radal corredora app uses **react-i18next** on top of **i18next**. UI copy is
Spanish (Chile) by default. **Every UI string goes through `t()`** — no hardcoded
literals in components.

---

## 1. Policy

- **Default locale: `es`** (Spanish, Chile). This is the domain language and
  must be **complete** — every key present with real copy.
- **Secondary locale: `en`** (English). It **mirrors the key structure** of `es`
  exactly (same namespaces, same keys). Missing/placeholder English is
  acceptable early, but the key set must match `es` 1:1.
- **Fallback:** `fallbackLng: "es"`. If an `en` key is missing, i18next falls back
  to the Spanish string rather than showing the raw key.
- Domain nouns (cliente, póliza, ramo, siniestro, UF, coaseguro) stay in Spanish
  even inside `en` where they are proper domain terms; translate only the
  surrounding UI chrome.

---

## 2. Files & namespaces

Translation files live at:

```
frontend/src/locales/{es,en}/<ns>.json
```

One JSON file per namespace, per locale. Namespaces mirror the modules:

| Namespace       | Scope                                             |
|-----------------|---------------------------------------------------|
| `common`        | App shell, nav, buttons, generic labels, toasts, estados shared across modules |
| `auth`          | Login screen, session, errors                     |
| `dashboard`     | Greeting, KPI labels, section titles, quick actions |
| `clientes`      | Clientes list + detail                            |
| `polizas`       | Pólizas list + detail, coverage analyzer labels   |
| `renovaciones`  | Renovaciones list + detail                        |
| `cotizaciones`  | Cotizaciones list + ofertas                       |
| `siniestros`    | Siniestros list + detail                           |
| `inspecciones`  | Inspecciones list + detail, checklist labels      |

`es` must contain all nine namespaces fully; `en` mirrors all nine.

## 3. Setup

`frontend/src/i18n/index.ts`:

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";

// eager-import JSON resources (or lazy-load via http-backend later)
import esCommon from "@/locales/es/common.json";
import enCommon from "@/locales/en/common.json";
// ...one import per ns/locale...

export const NAMESPACES = [
  "common", "auth", "dashboard", "clientes", "polizas",
  "renovaciones", "cotizaciones", "siniestros", "inspecciones",
] as const;

i18n.use(initReactI18next).init({
  resources: {
    es: { common: esCommon, /* ... */ },
    en: { common: enCommon, /* ... */ },
  },
  lng: "es",
  fallbackLng: "es",
  defaultNS: "common",
  ns: NAMESPACES,
  interpolation: { escapeValue: false }, // React already escapes
  returnNull: false,
});

export default i18n;
```

Import once in `main.tsx` (`import "@/i18n"`), before rendering `<App/>`.

**Language toggle.** A toggle in the top bar / sidebar calls
`i18n.changeLanguage("es" | "en")` and persists the choice to `localStorage`
(read it back in `init` via a small detector or manual `lng` resolution).

## 4. Usage in components

```tsx
// namespace via hook
const { t } = useTranslation("polizas");
<h1>{t("detail.title")}</h1>

// cross-namespace with prefix
const { t } = useTranslation(["polizas", "common"]);
<Button>{t("common:actions.save")}</Button>

// interpolation
t("dashboard:greeting", { name: user.nombre }); // "Buenos días, {{name}}"
```

## 5. Key naming conventions

- **Namespace = module.** Never repeat the module name inside the key.
- **Dot-separated, lowerCamelCase segments**, grouped by UI region:
  - `list.*` — table/list view (columns, empty states, filters)
  - `detail.*` — detail view (block titles, accordion headers)
  - `kpi.*` — KPI card labels
  - `actions.*` — buttons / quick actions
  - `status.*` — estado enum labels (mirror the DB enum values)
  - `fields.*` — form field labels & placeholders
- **Enum labels mirror DB values** so mapping is mechanical, e.g.
  `polizas:status.vigente`, `polizas:status.no_vigente`,
  `siniestros:status.en_documentacion`, `cotizaciones:priority.alta`.
- **Interpolation vars** are descriptive: `{{name}}`, `{{count}}`, `{{dias}}`,
  `{{uf}}`.
- **Plurals** use i18next suffixes: `kpi.polizas_one` / `kpi.polizas_other`.

---

## 6. Guardrails

- No literal user-facing strings in `.tsx` — lint/review rejects them.
- Adding a key to `es` requires the same key in `en` (keep them in sync; a
  parity check script can diff key sets across locales).
- Keep number/UF and date formatting in `date-fns` / `Intl` with the active
  locale; do not bake formatted numbers into translation strings.
