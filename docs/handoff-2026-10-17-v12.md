## 1. What v12 is — the product owner's decisions

1. **Pólizas are the home** (`/` → `/policies`). Journeys are **partial**: a broker starts from a policy
   PDF, from portal quotes, or from the full market process. The grupo-cuenta stays, but becomes a
   **viewer** that shows only the stages that actually happened (skipped stages are recorded as
   `is_skipped` events, never faked).
2. **Closed ramo catalogue** — 18 ramos × 54 subtipos (the team CSV + `PRO-05 Robo`), global Radal
   data. **Brokers can no longer create ramos** (so Radal can trace which ramos are processed most).
   This reverses the v7/v11 "Crear ramo" drawer.
3. **Cobranza in three levels per cuota** — `record` (registro) · `assisted` (asistida: Radal reminds
   the payer and asks the insurer) · `native` (Forpay checkout). Assisted is available on **any**
   policy at **any** time; when an insurer goes native its open cuotas upgrade by themselves. The
   broker never sees an insurer's Forpay onboarding status.
4. **Forpay is configured per insurer by RADAL** (Mantenedor console, platform users only) with
   per-broker overrides (contact e-mail, instructions, native opt-out).
5. **One generic webhook** for every provider account: query `account` + `sig` (HMAC) plus Forpay's
   own payload HMAC.
6. **No comprobante matching** — payments land in the insurer's account. Instead: mail that **asks the
   insurer** (status inquiries), inbound classification, and public links — every result is a
   *suggestion* a human confirms (non-negotiable 6). A signed provider webhook is the only money path
   without a human confirm.
7. Brokers are the only logged-in users. Insurers and insureds answer through **public share links**
   (WhatsApp-ready). No new viewer roles.
8. Radal mail = **Zoho `contacto@radalseguros.cl`** over `smtplib`/`imaplib`; brokers may connect a custom
   SMTP/IMAP server. Google/Microsoft OAuth = visibly disabled "pronto".
9. The **agent** gets policy/cobranza/RPA tools and **skills**.
10. **RPA**: Playwright, **HDI only**, as a showcase of a framework whose portal map is JSON.
11. **WhatsApp**: an enum value + a disabled chip; nothing is sent.
12. **Deploy**: NAT (cheapest first) — documented and scripted, not applied.
13. Responsive web app (brokers check from phones); no native app.

## 2. How it was built

An orchestrated multi-agent build. **Phase 1** (sequential) owned every shared file: 1a data model +
migration + seeds + settings + crypto + RBAC; 1b core services, seams, fakes, jobs framework, router
stubs; 1c frontend scaffold (routes, rail, namespaces, query keys); a gate that audited the models
column by column against `01-data-model.md`. **Phase 2** ran shared services (notifications, FX), then
parallel lanes **B1–B7** (backend) and **F1–F6** (frontend) each inside a declared file lane, then an
integration pass, reviewer/adversarial/QA passes, a fix pass, a demo-seed lane, a docs lane, and this
final regression. Shared files were frozen after phase 1; a lane that needed a change elsewhere had to
report it instead (several open items below exist for exactly that reason).

## 3. What was built, per area

**Data model** — 27 new tables (50 → 77) in 12 new model files, 28 additive columns on 7 existing
tables, every v12 enum in `app/models/enums.py`, no column widened. Two FK cycles via named `use_alter`
(`fk_collection_plan_mandate`, `fk_payment_evidence`). **`case_file.entry_origin` (new) carries the
team's *origen*; `case_file.origin` stays the v3 new/renewal/period_change axis.** Secrets
(SMTP/IMAP, Forpay, portal passwords) are Fernet-encrypted `*_ciphertext` columns, write-only in the
API (`app/core/crypto.py`). Tech-ref §19.2.

**Pólizas (B1 + F1)** — `/policies` is the home: KPI cards (vigentes, prima vigente, cuotas vencidas,
sin plan de pago, sin respaldo, vencen en 90 días), filters (q incl. dotted RUT, ramo → subtipo cascade,
compañía, computed estado, cobranza, faltantes, Mías), table ≥ md and card list < md. Two entry doors:
**Subir póliza** (reader; commits the extracted cuotas when Σ passes) and **Registrar a mano**
(`/policies/new`; two-mode `POST /policies`, colocación on demand, `SIN-N-{id}` placeholder number).
Detail adds Falta (operability with Spanish reasons + Completar), Partes (`PUT /policies/{id}/parties`),
Cobranza summary, Compartir and Viaje. The notification **bell** (two trays, Por hacer / Para saber)
lives in the Topbar; `/notifications` is the full page.

**Catálogo + viaje parcial (B1 + F5)** — `GET /catalog/lines` drives every ramo picker; ramo writes are
403 for broker users. `POST /case-files` takes subtipo + route; `skip-to` / `activate-stage`; the
account shows only the stages that happened. Uploading a policy into an open folder advances it.

**Cobranza (B2 + F2)** — `collection_installment.status` is now a **cache** of
`compute_installment_state` (`services/collection/status.py`); money moves only through the ledger
(`services/collection/ledger.py`). `/collections` = summary cards + Próximas · Vencidas · Al día ·
Saldadas, level badge (En línea / Asistida / Registro) with the server's reason, row actions (registrar
pago, promesa, PAC rechazado, confirmar, recordatorio with preview, consulta a la compañía, link de pago,
compartir, iniciar cobranza). `/collections/evidence` (Respuestas por confirmar) and
`/collections/inquiries`. Settings: cadence, tolerances, master switch, sender, templates + approval.
Daily `collection.clock` raises/escalates/closes the bell.

**Forpay (B3 + F3)** — `PaymentProvider` protocol, real `ForpayProvider` client (httpx), the
`FakePaymentProvider` for tests, checkout intents, `payments.sync` / `payments.payouts`, the generic
**webhook** (`POST /api/v1/webhooks/{provider}?account=&sig=`, dedup on signed fields, forged payloads
stored as `ignored` + 401, processing errors stored `failed` but still 200), and the **Mantenedor** console (`/platform/*`: insurer
profiles, provider accounts with write-only secrets + verify + 30-day secret rotation, channels matrix,
webhook inbox with reprocess, job runs). Broker side: `/payments/insurers` + per-insurer override.

**Correo + consultas (B4 + F3)** — `services/mail/sender.py::send_mail` is the one door out (Radal Zoho
box or a broker box; every send is a `mail_message`, `skipped` while `MAIL_ENABLED=false`).
`SmtpImapTransport` with an SSRF guard on broker hosts. `mail.poll` prefilters **before storing anything**
(Ley 21.719), classifies kept mail by AI (always an `extraction` row) and creates `payment_evidence`
suggestions. Status inquiries (`INQ-XXXXXX` token) with resend/cancel; payer notices by cadence.

**Links públicos (B5 + F4)** — `/s/:token` outside the shell, mobile-first, broker-branded. Insured
audience: cuotas, instructions, **Pagar** (native only), "Ya pagué · subir comprobante". Insurer
audience: report status per cuota. Mandatory expiry (60 d default, ≤ 365), revocation, view count,
narrow projection, every public write is a suggestion. `ShareDialog` with WhatsApp deep link.

**RPA (B6 + F6)** — `services/rpa/`: JSON step map (`selectors/hdi.json`) executed by an interpreter,

failure. Tested against a local fake HDI portal with real Chromium. How to fix a broken connector:
tech-ref §19.9.

**Agente (B7 + F6)** — 37 tools (11 + 26 new); write tools only propose an `agent_action` and reuse

(`collections_review`, `policy_intake`, `partial_journey`, `file_check`, `portfolio_analysis`,
`portal_quotes`); skill suggestion card in the agent page.

**Jobs + infra (phase 1b, B2, docs lane)** — `app/jobs` framework (one `job_run` per slot, three doors:
CLI, `POST /api/v1/internal/jobs/{name}`, `POST /events`), nine jobs + `noop`. `deploy/v12/`

**Demo world** — `python -m scripts.seed_v12_demo` builds *Corredora Demo SpA* on a throwaway SQLite

## 5. Errors made & corrections (candid retrospective)

Same discipline as v9/v10. **Most of these were invisible to `tsc`/`build`/pytest, which were green the
whole time** — they were caught by reviewer, adversarial and QA passes that drove the API and the UI.
Every one below was fixed in the fix pass, with tests where the fix was server-side
(`tests/test_v12_qa_fixes.py`, `tests/test_v12_security_fixes.py`); the corrections are as that pass
reported them, and its UI changes were re-checked in a browser only as far as §4's smoke reaches.

| # | What was wrong | Correction / lesson |
|---|---|---|
| 1 | A server **422 on a premium mismatch** surfaced as the raw axios toast *"Request failed with status code 422"*. | Show the server's Spanish `detail`. A generic client error is a dead end for the broker. |
| 2 | **Searching Cobranza by a dotted RUT** (`76.345.678-1`) returned 0 rows; Pólizas handled it. | Same RUT normalisation on both lists. Two lists of the same rows must accept the same query. |
| 3 | **"Recordatorio enviado"** toast even when the notice was **skipped** and no mail left. | The toast reads the returned status. A success message must reflect the outcome, not the HTTP 200. |
| 4 | **Naive UTC timestamps rendered as local time** — some screens were 3 h ahead. | Event timestamps serialised tz-aware UTC (`app/schemas/utc.py`). Contractual datetimes deliberately left as they were (see §6). |
| 5 | **Account-holder RUT in the insurer payment override** was neither validated nor normalised. | mod-11 + `BODY-DV` (non-negotiable 7) on that field too. |
| 6 | `broker_executive` could **replace the corporate logo** but not edit the broker profile. | Logo gated like the profile. Inconsistent gates on one object are a privilege leak. |
| 7 | **"Acciones pendientes" ignored skipped stages** and showed contradictory actions. | Pending actions read the partial journey (skipped stages excluded; antecedentes gaps hidden once the account reaches *Póliza emitida*). |
| 8 | **"Otras etapas" leaked a raw enum**: *"no alcanzable desde 'active'"*. | Spanish stage labels in server reasons. |
| 9 | **Settings fields rejected Chilean-formatted CLP** (`1.234.567`) and rendered decimals with a dot. | es-CL parsing and formatting in the settings inputs. |
| 10 | **Platform admin login landed on the broker `/groups` page**: a raw English error and "Nuevo asegurado" buttons that could not work. | Login goes to `/`, and `HomeRedirect` picks `/platform` or `/policies`. Verified live in this pass at both widths. |
| 11 | **The agent showed a raw English developer message** when no AI provider was configured. | 502/503/504 mapped to a localised line. |
| 12 | **The skill suggestion card was squashed at 375 px** (one or two words per line beside the buttons). | Card relaid out for narrow screens (not re-checked visually beyond §4's smoke). |
| 13 | **Evidence card said "La compañía informa"** for receipts the **payer** uploaded. | Copy chosen by evidence source. Who said it matters when a human must confirm it. |
| 14 | (found in this final smoke) The insured share page showed **"4 días de atraso" in red under a green "Pagada"** — the delay the cuota was paid with, read as an alarm. | `pages/public/share.tsx`: a paid cuota now reads "Pagada con N días de atraso" in neutral ink (new `share:public.installment.paidLate_*` keys). |

**Caught by the adversarial/security pass** (all fixed, pinned in `tests/test_v12_security_fixes.py`;
read from the test names — the most serious class of the build):

- **`javascript:` URLs** could be stored as an insurer `payment_url` / override portal URL and reach the
  **public share page** — now validated on create/update (`422`) and filtered on read, legacy rows included.
- **Unsigned webhook fields were trusted**: a mutated unsigned activation state could revoke a mandate,
  the unsigned `internalId` could retarget an activation, and a payment replay with a mutated unsigned
  currency was not a duplicate. Dedup keys and targeting now use signed fields only.
- **Cross-user / cross-tenant reach**: an inquiry could be sent through a colleague's personal mailbox;
  a policy (manual or via the agent) could attach another broker's private insurer.
- **Money**: a USD cuota could resolve native and a provider payment on it was booked as UF (now
  assisted, checkout refuses, provider amounts converted); a partial manual payment left an open Forpay
  link at the old amount (now superseded); the extraction Σ counted non-issued endorsements.
- **Bell**: the daily clock re-lit or closed chargeback and debit-rejection to-dos.

**Process errors, not code:** phase 1a did not write the core seams the lanes depended on (status,
resolver, provider/transport protocols, share-link skeleton, fakes) — a separate 1b step had to be
inserted before the lanes could start. The contract docs drifted from the phase-1 build on four names
(`entry_origin`, `MailMessageStatus.skipped`, `run_job(db, …)`, `notify_ops(db, …)`); the gate caught
them and rewrote the docs before the lanes read them. Lesson: **the as-built document must exist before
parallel work starts, and it must win over the plan.** Individual lane crashes/restarts are not recorded
in the repository and are not reconstructed here.

## 6. Migration & deploy steps

pushing code before the 28 columns exist 500s nearly every policy/cobranza/case-file query. There is
still **no Alembic** (non-negotiable 10).

cd backend
# 0) review the plan offline (no connection)
.venv/bin/python -m scripts.migrate_case_files --dialect mysql --pass v12
# 1) open RDS (docs/deployment.md "Option A"), 2) SNAPSHOT
aws rds create-db-snapshot --profile radal --db-instance-identifier radal-dev-db \
    --db-snapshot-identifier radal-dev-pre-v12-$(date +%Y%m%d)
# 3) dry run (exit 1 = drift) → apply → re-run must print nothing to do
.venv/bin/python -m scripts.migrate_case_files --url "$RDS_URL"
